# 项目存档的格式与并发边界

`nin-project` 的辅助脚本使用 Python 标准库保存本地项目记录。它负责身份、格式、历史和更正关系，不判断商业结论是否正确。业务数据保存在用户指定项目目录，不能放进技能安装目录。

## 数据格式

每个项目根目录有 `project.json`，内容包含 `schema_version: 1` 和稳定的 `project_id`。每次保存向 `snapshots/` 添加新的 UTF-8 JSON，不覆盖历史文件。记录包含输入内容以及：

- `schema_version`：当前为 `1`。
- `id`：本次记录的 UUID，32 位十六进制、不带连字符。
- `created_at`：带时区的 ISO 8601 生成时间；恢复排序使用该字段，不使用文件修改时间。
- `project_id`、`title`、`summary`：非空字符串。
- `claims`：判断 ID、内容、证据类型、来源、观察时间和显式更正关系。

证据类型为 `user_statement`、`material_record`、`external_verified`、`inference`、`hypothesis`。保存不会自动提升证据强度。相同判断 ID 可以出现在多份快照中，但其完整内容必须相同；更正必须使用新判断 ID，以 `supersedes` 指向已存在的旧判断。

完整输入格式、无 Python 手工落盘示例和目录结构见 [记录格式与操作](../skills/nin-project/references/project-records.md)。手工保存不仅要写快照，还要保留同一项目的根元数据；少写 `project.json` 会被读取器报告为身份不匹配，不会自动猜测项目归属。

## 保存事务与进程锁

保存对同一项目持有操作系统互斥锁，覆盖以下步骤：

1. 重读根元数据和全部历史快照。
2. 检查格式、项目身份、同判断 ID 的内容和更正引用。
3. 如为新项目，独占创建根元数据。
4. 独占创建新的快照，并回读核对。

Windows 使用 `msvcrt.locking` 锁定 `.project-store.lock` 的第一个字节；macOS/Linux 使用 `fcntl.flock` 锁定该文件。无需第三方包或常驻服务。等待使用短轮询和最长 30 秒期限；忙碌超时会失败并提示稍后重试，不跳过锁继续写入。

锁文件永久保留，但锁由打开的文件描述符持有，进程正常退出或被终止时由操作系统释放。**不要删除锁文件来解锁**：删除后可能出现仍在等待旧文件的进程和使用新文件的进程，破坏互斥。不同项目使用不同锁文件，不会互相阻塞。

该机制保护所有使用本脚本的保存进程，包括不同终端发起的保存。同 ID 异文争写时，先取得锁的进程可保存，后取得锁的进程重读新历史后拒绝改写；不同判断 ID 的合法保存会依次完成。它不防止外部编辑器、其他版本脚本或手工文件操作，手工回退须与自动保存错开。

## 读取与冲突

`list` 和 `show` 不创建目录或改动记录。格式错误、身份不匹配和跨文件同判断 ID 的异文通过 `errors` 返回。判断冲突提供 `claim_id`、当前路径和另一来源 `conflicting_path`，以便核对原始证据。

为便于检查问题，读取仍可返回其他有效记录以及有冲突的可解析记录。调用方必须检查 `errors`，不能把有返回记录等同于完整、无冲突恢复。任何已有错误都会阻止新的保存，脚本不自动删除历史、选定“最新事实”或改写旧判断。

读操作不持写锁，不能视为整个项目的事务性快照。若与正在进行的保存相遇，可能暂时看不到新记录，或将正在写入的文件报告为不完整；待保存结束后重读。写入中断留下的坏文件会持续显式报错，需要人工核对，不会被悄悄跳过后继续追加。

## 验证范围

从仓库根目录运行：

```text
python -B -X utf8 scripts/test_project_store.py
```

测试覆盖中文项目身份、只读不建目录、历史不可覆盖、显式更正、未知引用和非法证据类型、坏文件可见、按记录时间恢复，以及以下回归场景：

- 直接创建完整手工存档，再由 CLI 恢复，并继续保存显式更正。
- 缺少根元数据的手工快照明确报错，不偷偷补项目身份。
- 模拟旧存档已有同判断 ID 异文，`list`/`show` 都报告双向来源，继续保存被拒绝。
- 两个真实子进程竞争同判断 ID；先暂停第一个进程于历史读取之后，确认第二个被锁阻挡，释放后仅一个成功。
- 四个真实子进程同时首次保存不同判断，全部完成且历史无冲突。
- 另一个进程持锁时超时；终止持锁进程后可重新取得锁并保存。

这些是本地文件与脚本行为测试，不证明业务结论正确，也不证明技能在所有模型中的输出质量。Windows 分支已在本轮验证；macOS/Linux 使用标准库对应锁原语，仍应在其实际宿主运行相同测试。本工具针对本地文件系统；网络共享盘的锁语义、云盘同步冲突、断电持久性和不遵守协议的写入者不在当前保证范围内。
