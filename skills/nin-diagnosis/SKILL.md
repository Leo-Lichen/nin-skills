# 项目诊断

交付一份基于已有证据的项目判断，说明哪些环节已有支撑、哪些尚未成立、下一步最值得验证什么。诊断的是项目的商业假设与执行条件，不根据失败或拖延推断人的心理。

## 识别判断对象

先从上下文提取：用户要作的决定、业务阶段、经营目标、对象与场景、资源约束。稳定盈利、增长融资和个人试水的评价权重不同。没有明确目标时，只追问会改变判断的关键问题；已有资料可分析的部分先给阶段性判断，不先发长问卷。

聚焦问诊从具体断点进入；用户要完整体检才展开全图。两种方式由诉求决定，不让用户再次选择已表达的模式。

原书序言的六因素把创新能力、创业方法、创业精神，与文化观念、政策法规、创业服务分为内外两组（PDF 5—7）。用它提醒归因边界：判断既检查团队可改变的条件，也保留外部约束，不把所有问题归为个人意志。

## 推理路径

1. **画出当前交易。** 谁使用、谁付钱、为什么付、得到什么、谁交付、成本是什么。尚无交易时标出设想，不以“没有公司”直接判失败。
2. **用三价值逐项判定。** 问题：发生在谁身上，强度及替代办法如何，有什么需求证据。方案：对应哪个痛点，实际效果与比较优势如何。团队：关键工作能否完成，实际能力、资源及缺口是什么。说明相互制约关系，不能用团队光环补需求证据。
3. **用七问查关键缺项。** What/Why/How/Who/When/Where/How much；Who 同时覆盖客户、用户与执行者，How much 同时覆盖成本、数量、质量和投入产出。七问是内部检查工具，不要求每次逐项提问。
4. **用九模块定位断点。** 简介、市场、产品、模式、团队、进展、战略、风险、融资。判断哪个缺口真正阻止本次决策，避免把所有问题平均用力。
5. **竞争解释。** 对“无人付款”“订单很多却缺钱”等现象，保留有依据的不同解释，指出什么观察能区分它们。原因尚未确定就给条件分支，不能把最顺口的解释写成事实。
6. **给出有限结论。** 分清“已有证据支持继续某一步”“证据不足，应先验证”“出现反证，应修改或暂停具体投入”。不把这些状态变成成功概率或统一总分。

复杂体检、信息冲突或需要例子时，读取 [判定规则与完整案例](references/diagnosis-cases.md)。不必每次重读整套书。

## 证据的用法

结论注明用户陈述、材料记录、外部核验、推断或待验证。保留时间、样本和口径：十人点赞、一份意向、一笔回款，分别支持不同强度的判断。利润、收入和现金分开；融资、奖项和顾问名单不能替代需求验证。

不补写未报告的结果。例如“23 人中 20 人说需要”不等于另外 3 人说不需要；他们可能拒绝、犹豫或未表态。用户只列举部分来源或案例时，不据此宣布全量、总额或其他类别为零。算术可得的剩余人数与其真实回答要分开。

材料矛盾时并列来源并缩小可判断范围，不随意选择更乐观的数字。需要当前行业规模或政策才能判断时再核验；没有检索能力时明确保留该项，不引用书内历史数字冒充现状。

## 交付与结束

按问题大小组织，不机械铺表。完整体检至少给出：

- 一段项目现状与当前决定；
- 三价值或九模块中与结论有关的“判断—证据—缺口”；
- 最关键的瓶颈及它为什么比其他问题更优先；
- 一项可执行验证：对象、动作、观察结果、资源约束和复查条件；
- 哪些新证据会改变本次判断。

当用户已经拿到本次决定的条件、关键未知与可执行下一步，即完成诊断。无法确定可行性本身可以是有效结论，但要说清是缺证据还是出现反证。不能以“还要进一步研究”结束全部工作。

## 交接

需要设计新验证时用 [experiment](../nin-experiment/SKILL.md)；需要澄清需求用 [market](../nin-market/SKILL.md)；交易或成本不清用 [model](../nin-model/SKILL.md)；资源路径不匹配用 [strategy](../nin-strategy/SKILL.md)。传递本次结论和证据，不重新问相同问题。只继续完成用户任务所必要的环节，其他作为建议。
