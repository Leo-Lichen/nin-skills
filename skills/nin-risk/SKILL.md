# 风险管控：把可能出问题的地方落到触发条件

原书将风险归为宏观、产品、运营、团队四类。分类用于检查遗漏，不能代替判断轻重。重点是识别用户当前决策会暴露在哪里，并为最重要的不确定性安排应对。

## 从具体决策进入

先复用项目材料、当前计划和约束。用户只要审查一次扩张，就围绕扩张检查；用户要求完整风险清单，再覆盖四类。不要因为做风险检查就无限扩大到一切可想象的灾难。

区分已发生问题、尚未发生风险、已知约束和信息缺口。已发生的问题需要处置，不再只写“密切关注”。未知并不等于大概率发生，但若决定性假设未知，就应明确其对决策的影响。

## 判断流程

### 1. 沿经营链找失效点

从目标倒看依赖：客户能否接触、是否愿意买、产品能否交付、供应是否稳定、钱怎么流转、关键人员与合作是否可用。选取“如果它不成立，计划将不能继续”的假设。

用四类检查遗漏：

- **宏观**：外部规则、商业趋势、竞争与替代方式对项目的具体影响。
- **产品**：研发进度、质量、供应交付、技术与知识产权依赖。
- **运营**：交易结构、获客、成本、回款、流程、资质等经营约束。
- **团队**：能力缺口、关键人员、权责利、协作和合作稳定性。

当前法规和许可是否满足，必须以适用地区、主体和业务事实及当前来源判断；原书案例只能说明风险类型，不能证明今天的法律结论。

### 2. 把空泛风险改成失效链

采用“条件或事件 → 影响哪一步 → 导致什么后果”的表达。例如“唯一供货商交期超过客户允许日期 → 无法按承诺交付 → 触发退款和现金缺口”。

标明已有证据、推断和未知。把同源的连锁后果放在一起，不将一个根因重复算成多项独立风险。也检查共同依赖：所谓两个备用渠道可能都依赖同一平台或供应商。

### 3. 排优先级

判断影响程度、暴露时间、可逆性、预警是否来得及、当前证据支持的发生可能性。优先处理会在下一关键节点前造成不可承受损失、且难以补救的事项。

没有可靠数据就使用明确的定性理由，不伪造精确概率或把主观数字相乘冒充科学评分。概率未知但后果足以使计划无法继续时，可采用限额投入、备选路线或先核实的办法。

### 4. 写可执行应对

每项重要风险应有：预防措施、触发信号、触发后的动作、负责者、必要资源、最晚启动时间和残余风险。措施至少改变发生可能性或后果之一；“加强管理、提高警惕”本身不是方案。

可选动作包括减少暴露、先验证关键假设、准备替代方案、调整顺序、限制投入或接受有理由的剩余风险。备选供应商、保险、协议和融资只有条件明确且可用时才算应对资源。

### 5. 检查应对本身

应对可能引入新成本和新依赖：备货占现金、备用供应商增加质检工作、外包增加协调成本。确认行动能在损失发生之前奏效，且负责人真有能力和资源完成。

对外版本可以简洁，但不能把内部未解决的风险写成已解决。风险被清楚管理能增加可信度；风险登记本身不保证“可控”。

## 交付与完成条件

按用户需要交付简短结论或风险表：失效事件 / 依据与未知 / 后果 / 优先原因 / 预警 / 应对与责任 / 残余风险。最后指出当前应先改变的一个决策或应先核实的一条信息。

重大风险已排序、至少有能执行的首项措施、无法消除的暴露已说清，即可完成。不要求所有风险清零。条件变化、预警触发或备选方案失效时复核。
