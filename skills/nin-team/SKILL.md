# 团队与资源：证明关键工作有人做得成

以韩树杰《创业地图》的团队组织四要点为基础：核心团队、股权结构、公司架构、专家顾问。先从项目要完成的事情看团队，再从人员经历看能力，避免把名气、人数和头衔当成交付保证。

## 接住当前任务

先使用上下文中已有的业务、阶段、成员和合作材料。用户在改团队页，就交付团队页及缺口；用户在找合伙人，就分析关键工作与合作条件；不强制重做整份商业诊断。

若下一里程碑不清，只补问会影响用人判断的结果和时间。其余未知信息可留待核验，继续完成能力拆解。先分清成员已经加入、兼职承诺、接洽中、仅被提名，不能合并成“团队已齐”。

## 判断流程

### 1. 从里程碑反推关键工作

把下一阶段结果拆成实际工作，例如找到首批付款客户、完成交付、获得必要资源、管住回款。只保留决定成败的工作，不默认早期团队需要完整大公司岗位。

每项工作判断：需要何种能力、何种权限、多少可用时间、什么交付证据。一个人可以承担多项，但时间相加后要可行；“人人负责”应追到最终负责人和协作人。

### 2. 匹配人和证据

区分三层，不能互相替代：

- **经历相关**：做过相近任务，说明领域、本人角色和时间。
- **结果相关**：取得何种结果，说明指标口径、本人贡献及可核对材料。
- **投入可用**：这次承诺什么工作、何时可投入、与其他职责是否冲突。

过去成功不能保证本项目成功；没有亮眼履历也不能直接判不适合。对缺经验的人，看已有试做、学习速度、具体交付和反馈；必要时建议一个小范围合作任务来检验匹配。这个试做方案是应用扩展，不冒充原书标准。

### 3. 检查协作和利益安排

围绕真实分歧检查“责、权、利”：谁决定产品范围、支出、客户承诺和人员安排；意见不一致如何处理；成果与投入如何记录；贡献变化、离开或引入新成员如何协商。

股权比例只是输入之一。还需知道形成原因、出资与劳动投入、长期责任、已有协议、表决和退出约定。不要仅凭 50/50 或创始人持股较高判定必败，更不把书内历史比例当现行控制权法律结论。可形成待协商议题和专业核验清单；不替用户设定法律效力或自动改协议。

### 4. 核对外部资源

顾问、渠道、技术授权、场地、供应与合作资源要回答：由谁提供、双方是否认可、能提供什么、何时提供、附带什么条件、目前做过什么、失去它会怎样。认识某人不等于可以动用其资源；未获双方认可的顾问身份不能写成已聘任。

有条件的支持标出条件，不能与可立即调用的资源相加。对关键单点依赖提出可行替补或降级方案，而不是把所有外部能力都招进公司。

### 5. 给出最小补位方案

按“阻断里程碑程度、当前可替代性、投入成本”排序。比较内部重分工、短期合作、外包、招聘、调整目标等实际可行选项，解释为什么优先某一种。没有证据时保留条件判断，不给成员贴人格标签。

## 交付与完成条件

输出规模随问题大小调整，完整诊断包含：

1. 团队能否支撑下一里程碑的结论及条件。
2. 关键工作表：工作 / 负责人 / 相关证据 / 可用投入 / 缺口。
3. 最重要的协作或资源依赖，以及需要澄清的约定。
4. 一项补位动作，包含交付标准、责任人和期限；尚未约定者明确写“待确认”。

用户要团队介绍时，直接写可用版本，将已证实贡献与拟承担职责分开。没有证明的名校、奖项、职务、合作背书不能补写。引用材料区分用户陈述、材料记录、外部核验和分析推断，并保留日期。

当关键任务已有明确承接判断、最紧要缺口和补位动作时即可完成，不要求先补齐所有岗位。新增关键成员、资源承诺变化或里程碑改变时重检匹配。
